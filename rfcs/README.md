# 规范变更提案（RFC）

本目录存放对**冻结规范**的变更提案。

v3.0 §18.3 规定，任何拟议变更 MUST 提交至规范仓库并经评审。本目录是那条规定
的落点 —— 在此之前它没有落点，因此无法执行。

---

## 1. 什么需要提案

判据是**是否改变语义**，与改动大小无关。

| 变更 | 走哪里 |
|---|---|
| 新增不变量、新增合规等级、新增错误码、新增 Extension 章节 | 本目录。§18.1 归类为 `3.x.0` |
| 修改任一冻结不变量、修改层级方向、修改核心概念 | 本目录。§18.1 归类为 `4.0.0` |
| 澄清歧义文本、修正拼写与格式、补充非规范附录 | 不走本目录。§18.4 的勘误，就地写入正文并在 [`docs/spec/CHANGELOG.md`](../docs/spec/CHANGELOG.md) 留一条 |

**边界情况**：若一处"澄清"会使两个原本都能自称合规的实现变成只有一方合规，
它改变的是语义，走提案。勘误 E-I（`Constraint` 的匹配语义）就是这样一类 ——
它被归类为新增不变量，并因此产生了协议版本 3.3.0。

---

## 2. 提案的生命周期

```
Draft ──► Review ──► Accepted ──► Implemented
  │          │           │
  └──────────┴───────────┴──► Rejected / Withdrawn
```

| 状态 | 含义 |
|---|---|
| **Draft** | 作者正在写。尚未请求评审 |
| **Review** | 已请求评审，等待 §18.3 要求的评审意见 |
| **Accepted** | 评审通过，裁定已定。规范正文尚未修改 |
| **Implemented** | 已写入规范正文，协议版本已按 §18.1 更新 |
| **Rejected** | 评审未通过。**文件保留**，并须写明替代路径 —— 否决的理由比提案本身更有用，它记录了什么不可以再提一次 |
| **Withdrawn** | 作者撤回 |

**Accepted 与 Implemented 分开**是有意的：裁定与落笔是两件事，前者可能远早于后者。
只有 `Implemented` 的提案才构成规范的一部分。

**被否决不等于问题不成立。** 提案可能在评审中被证明过于宽泛、无法执行，或把几个正交的
问题捆在一起。此时正确的结果是 `Rejected` 加一条更小的替代路径 —— 而不是把提案
改到能被通过为止。

---

## 3. 评审要求

§18.3 要求**至少两名独立实现者**评审。此处的"独立"指：

- 不是提案作者；
- 各自维护一份该层的实现。

**当前状态。** 本仓库有两份实现：TypeScript 参考实现（三层）与 Go 实现
（仅 Composition Core）。因此：

```
Composition Core 的变更     可满足：两份实现都在
Interaction 的变更          只能取得一份实现的评审
State Mode 的变更           只能取得一份实现的评审
```

在只有一份实现的层上，提案 MUST 在状态行注明 `评审：单实现`。这是一项**已知限制**，
不是豁免 —— 它使缺口可见，而不是让 §18.3 被静默地绕过。

---

## 4. 一份提案必须回答的问题

模板见 [`0000-template.md`](./0000-template.md)。必答项：

1. **§18.1 归类**：`3.0.x` / `3.x.0` / `4.0.0` 中的哪一类，以及理由。
2. **改变什么语义**：改前与改后，各自如何判定。
3. **为什么不能是现状**：不采纳会怎样 —— 这类问题此前**实际发生过**吗？
   发生了就给出具体例子。
4. **对既有实现的影响**：哪些实现会从合规变成不合规。
5. **一致性如何验证**：新增或修改哪条不变量，由哪个测试覆盖（§19.2 要求每条不变量至少一个测试）。
6. **`eappVersion` 的变化**：协议版本是否因此改变，以及不实现该变更的实现应报告什么。

---

## 5. 落笔

提案被 `Accepted` 之后：

1. 修改 `docs/spec/` 下的正文；
2. 在 [`docs/spec/CHANGELOG.md`](../docs/spec/CHANGELOG.md) 登记，并给出协议版本的变化；
3. 更新所有受影响的不变量与测试 —— [`check-invariants`](../tools/check-invariants.mjs)
   会拒绝"写了不变量但没有测试"的状态；
4. 更新受影响的参考页与指南。**复述过被改内容的页面必须同步**
   —— [`check-duplicates`](../tools/check-duplicates.mjs) 检查同名类型的成员是否一致，
   但散文体的复述由人负责；
5. 把提案的状态改为 `Implemented`，并注明协议版本。
