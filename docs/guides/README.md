# 指南

面向**使用者**的非规范性文档。规范定义规则，指南说明**规则的用法**。

指南按任务组织，回答"我要做 X，怎么做"，因此可以跳读。
每份指南只解释规范已有的语义，MUST NOT 新增规则
（[`docs/STYLE.md`](../STYLE.md) §1）。

| 指南 | 读之前需要知道 | 读完会 |
|---|---|---|
| [概念：三层心智模型](./concepts.md) | 无 | 说清 Composition / Interaction / State 各自回答什么问题，以及什么不属于协议 |
| [快速上手](./getting-started.md) | 无 | 知道本仓库交付什么、规范怎么读、想做的事对应哪一节、本仓库怎么验证 |
| [写一个插件](./write-a-plugin.md) | 概念 | 写出一个能被发现、连接、激活、调用的插件 |
| [实现一个 Transport](./write-a-transport.md) | 概念（第 2、7 节） | 使 EaPP 运行于任意消息系统之上 |
| [用另一种语言实现 EaPP](./implement-in-another-language.md) | 无 | 知道必须实现什么、可以跳过什么 |
| [写一个 Extension](./write-an-extension.md) | 概念、写一个插件 | 知道协议之外的语义如何用既有机制表达 |

## 三者的分工

```
指南     "我要做 X，怎么做？"       按任务组织，可以跳读
参考     "这个实体在哪里定义？"      按实体组织，是索引页：
                                 小节号 + 不变量 + 错误码，不重述语义
规范     "规则是什么，谁说了算？"    规范性，唯一裁决者
```

参考页是**索引**：实体的语义由 [`docs/spec/eapp.md`](../spec/eapp.md) 定义，
参考页只指出那处在哪一节、牵涉哪些不变量与错误码。
三者冲突时以**规范**为准。指南与参考页都是它的解释。
